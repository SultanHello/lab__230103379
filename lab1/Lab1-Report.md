# Lab 1: Fork-Join Model, Team Creation, and Thread Scoping

**Language:** Java 17  
**Experiment run:** 24 September 2026  
**Program:** `ForkJoinLab1.java`

## 1. Objective

The experiment creates a fixed-size `ForkJoinPool`, submits parallel work items, and waits for them to finish. It compares the time to create and join pools of different sizes, observes that task execution order can vary, and measures CPU use while each task performs a CPU-bound square-root loop.

## 3. Method

The source was compiled with `javac ForkJoinLab1.java`. For the timing sweep, the program used `System.nanoTime()`, two warm-up runs per team size, then five measured runs for each P = 1, 2, 4, 8, 16, 32, 64. `workIterations=0` isolates pool/task overhead as much as this simple experiment allows. The ten-run log was generated by starting the program ten times. For the CPU observation, the program was run with 2,000,000 square-root-loop iterations per task and sampled with macOS `top` once per second.

The timing includes construction and shutdown of a new pool, task submission, task completion, and result aggregation. This is a small-operation benchmark, so timer noise and JVM/runtime overhead are a substantial part of the result.
